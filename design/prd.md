## 1. 产品定位与目标

### 1.1 一句话定位

**面向城市年轻白领的匹克球兴趣内容平台**：一个"看得进去、学得会、找得到、想收藏"的轻量产品，把匹克球的资讯、教学、场地、装备四类内容集中在一处，让刚入坑的人不用在多个平台之间来回跳。

### 1.2 产品要解决的问题

| 用户痛点 | 产品解法 |
| --- | --- |
| 匹克球信息散落在小红书、抖音、公众号，找起来零散 | 每日资讯统一聚合，按主题分类，一个入口看完 |
| 新手不知道从哪学，规则、握拍、发球全靠零散视频拼 | 教学模块按"入门→基础动作→规则→进阶"结构化分层 |
| 想找好看、能出片的球场，但没有专门渠道 | 最美场地模块，以图片为主、标签筛选、地点线索清楚 |
| 想买拍子、球、服饰，但不知道什么款式适合新手 | 装备展示模块，只做种草与参数浏览，不做交易 |
| 看到一个好内容想留着，下次又找不到 | 全局收藏 + 双端同步，小程序收藏的内容 APP 里也在 |

### 1.3 产品目标（可衡量）

| 目标 | 衡量方式 |
| --- | --- |
| 降低新手进入门槛 | 新用户首次进入 3 分钟内可触达至少 2 个模块内容 |
| 内容消费成立 | 人均单次会话浏览内容数 ≥ 3 |
| 收藏行为成立 | 会话收藏转化率 ≥ 8% |
| 双端一致性 | 收藏在双端一致率 ≥ 99.9%（服务端为准） |
| 轻量不打扰 | 无强制登录、无强制弹窗、无交易链路打断 |

### 1.4 产品调性（功能层，不涉及视觉）

- **轻**：单页信息不堆砌，一屏一个主任务。
- **快**：任何内容 2 次点击内可进入详情。
- **不打扰**：不做开屏广告、不做强制登录、不做诱导分享。
- **可信**：内容有来源、有更新时间；装备参数标明为参考信息。

## 2. 目标用户

### 2.1 核心用户：城市白领匹克球新手/轻度玩家

| 维度 | 描述 |
| --- | --- |
| 年龄 | 22–35 岁 |
| 城市 | 一二线城市为主（北上广深、成都、杭州等） |
| 职业 | 互联网、金融、设计、营销、外企职员等 |
| 收入 | 8K–30K/月 |
| 运动频次 | 每周 0–2 次，多在周末或工作日晚上 |
| 设备 | iPhone / 安卓旗舰为主，微信使用时长高 |
| 内容习惯 | 短视频 + 图文混看，偏好短、直观、有图的内容；对"出片"和"颜值"敏感 |
| 决策习惯 | 先看别人的实拍和评价，再决定去哪、买什么 |

### 2.2 用户细分（用于内容策略）

| 类型 | 特征 | 主要诉求 | 对应模块 |
| --- | --- | --- | --- |
| A. 观望型（未打球） | 被朋友/社交平台种草，还没上手 | 这运动难不难？贵不贵？在哪打？ | 教学（入门）、资讯、场地 |
| B. 新手型（1–3 个月） | 打过几次，动作不规范 | 规则、握拍、发球、常见错误 | 教学（基础动作/规则） |
| C. 稳定型（半年以上） | 每周固定打，有球友圈 | 新场地、新装备、赛事和圈内动态 | 资讯、场地、装备 |
| D. 社交展示型 | 打球主要为拍照、发朋友圈 | 好看场地、好看穿搭、出片角度 | 场地、装备 |

### 2.3 次要用户

- 大学生、轻运动爱好者、健身人群。
- 场地经营者（只作为内容提供方，不做商家端）。

### 2.4 用户使用环境假设

- 网络：地铁/通勤场景弱网比例高，必须容忍弱网。
- 时间：单次会话 3–8 分钟，碎片化。
- 姿态：单手竖屏操作，拇指可达区域集中在屏幕下半部分。

## 3. 核心使用场景与用户故事

### 3.1 场景清单

| 编号 | 场景 | 触发时机 | 关键路径 |
| --- | --- | --- | --- |
| S1 | 通勤碎片刷资讯 | 早晚通勤、排队 | 打开小程序 → 首页信息流 → 资讯详情 |
| S2 | 打球前临时补课 | 出门前、球场边 | 教学 Tab → 分类 → 教学详情（短视频） |
| S3 | 周末找场地 | 周四—周六 | 场地 Tab → 筛选 → 场地详情 → 收藏 |
| S4 | 装备种草比款 | 想买拍/买服饰时 | 装备 Tab → 品类筛选 → 装备详情 → 收藏 |
| S5 | 收藏沉淀回看 | 想起来时 | 我的 → 我的收藏 → 分类型查看 |
| S6 | 跨端接续 | 小程序收藏后回家用 APP | APP 我的 → 收藏 → 看到同一条记录 |
| S7 | 分享给球友 | 看到好内容 | 详情页 → 转发（小程序卡片 / APP 外链） |

### 3.2 用户故事（User Story）

**US-01（观望型）**
作为刚听说匹克球的白领，我想在 3 分钟内搞懂"这运动是什么、难不难、要不要花钱"，这样我能决定要不要去试一次。
→ 验收：首页可通过 Banner 或信息流触达「匹克球是什么」入门内容；教学 Tab 有「新手入门」分类。

**US-02（新手型）**
作为刚打两次的新手，我想在去球场前 10 分钟内看懂发球规则和握拍要点，这样上场不尴尬。
→ 验收：教学详情支持短视频 + 分步骤图文；单条教学可在 3 分钟内读完。

**US-03（社交展示型）**
作为想拍照发朋友圈的人，我想筛出"出片"的场地，看到实拍图和场地特色，这样我能决定周末去哪。
→ 验收：场地 Tab 有「网红出片」筛选标签；详情页有多图预览与场地特色描述。

**US-04（装备种草）**
作为想买第一支拍子的新手，我想看不同拍子的外观、重量和适合人群，先收藏几款再对比。
→ 验收：装备详情含规格参数区；收藏后可在我的人中找到。

**US-05（跨端用户）**
作为上班用小程序、回家用 APP 的人，我希望收藏不用做两遍。
→ 验收：同一账号在小程序收藏的内容，APP 下拉刷新后可见；取消收藏同样同步。

**US-06（弱网用户）**
作为地铁上刷内容的人，我希望没网时不要白屏，能看到已有内容并能重试。
→ 验收：弱网下展示骨架屏 → 失败占位 → 点击重试可恢复。

    ├── 意见反馈

### 5.2 底部 Tab 定义

| 序号 | Tab 名 | 图标语义（功能层描述） | 默认页 |
| --- | --- | --- | --- |
| 1 | 首页 | 房屋/聚合 | 推荐聚合 |
| 2 | 资讯 | 报纸/闪电 | 资讯列表（全部） |

### 5.3 导航规则

1. Tab 切换不保留滚动位置（重新进入回到顶部）；同一 Tab 重复点击回到顶部。
2. 详情页使用页面栈（navigateTo），返回回到来源列表并保留滚动位置与筛选条件。
3. 首页跳详情后返回首页，保留当前信息流位置。
4. 搜索结果页进入详情，返回搜索页并保留关键词与结果。
5. 页面栈深度上限 10，超出时最底层页面被回收。

## 6. 全局功能规范

### 6.1 账号与登录

| 项 | 规则 |
| --- | --- |
| 是否强制登录 | 否。浏览、搜索、看详情全部免登录 |
| 需要登录的动作 | 收藏 / 取消收藏 / 意见反馈（可选登录）/ 账号绑定 |
| 小程序登录方式 | 微信一键登录（wx.login 取 code → 后端换 openid/session） |
| APP 登录方式 | 手机号验证码登录；微信快捷登录（需安装微信） |
| 账号唯一标识 | 服务端 userId（业务主键），微信 openid/unionid 为关联字段 |
| 昵称头像 | 小程序取微信昵称头像（用户授权）；APP 手机号登录默认"匹小将用户"+ 默认头像，可在个人中心修改 |
| 登出 | 我的 → 账号与绑定 → 退出登录；登出后收藏数据保留在服务端，重新登录恢复 |

**登录拦截交互（关键）**

- 用户点击收藏但未登录 → 不弹全屏登录页，弹出**底部半屏登录引导卡**：
  - 标题：登录后即可收藏
  - 副文案：收藏的内容可在小程序和 APP 之间同步查看
  - 主按钮：微信一键登录（小程序）/ 手机号登录 + 微信登录（APP）
  - 次操作：暂不登录（关闭弹层，继续浏览）
- 用户完成登录后 **自动继续执行原收藏动作**（不要求用户再点一次）。
- 用户取消登录，收藏图标保持未收藏状态，无 toast 报错。

### 6.2 收藏（核心全局能力）

**收藏对象类型（contentType 枚举）**

| 枚举值 | 含义 | 对应详情页 |
| --- | --- | --- |
| `news` | 资讯 | 资讯详情 |
| `course` | 教学 | 教学详情 |
| `venue` | 场地 | 场地详情 |
| `gear` | 装备 | 装备详情 |

**收藏规则**

1. 收藏是**服务端单一事实源**，不做本地收藏缓存，不做游客收藏。
2. 点击收藏 → 先本地乐观更新 UI（图标变实心 + 轻微动效）→ 调用接口：
   - 成功：保持实心，轻 toast「已收藏」；
   - 失败：回滚为空心，toast「操作失败，请稍后重试」；
   - 超时（>8s）：视为失败并回滚。
3. 再次点击已收藏内容 → 取消收藏，同样乐观更新 + 失败回滚，toast「已取消收藏」。
4. 同一条内容在双端、在列表页与详情页，收藏状态必须一致（同一 contentId + contentType）。
5. 防抖：同一卡片 1.5s 内重复点击，以最后一次状态为准，避免连点产生反向结果。
6. 收藏状态在以下时机从服务端刷新：进入列表页、下拉刷新、进入详情页、从其他页面返回、切前台。

**收藏计数**

- 我的页面统计区展示 4 类收藏数量（资讯/教学/场地/装备）+ 总数。
- 计数由服务端返回，不从本地累加，双端显示一致。

### 6.3 全局搜索

| 项 | 规则 |
| --- | --- |
| 入口 | 首页、资讯、教学、场地、装备页顶部搜索框；我的页面无搜索 |
| 搜索范围 | 资讯标题+摘要、教学标题+简介、场地名称+特色、装备名称+卖点 |
| 触发 | 输入即搜（防抖 400ms）；空关键词不请求 |
| 结果组织 | 默认「综合」排序：按相关度，同类型聚合分组；顶部可切换类型 Tab（全部/资讯/教学/场地/装备） |
| 结果项 | 标题（关键词高亮）+ 类型标签 + 一行摘要 + 封面缩略图 |
| 历史记录 | 本地保存最近 10 条搜索词，可单条删除、可全部清空（仅本设备，不同步） |
| 热词 | P1：搜索页展示 6–8 个运营配置热词 |
| 无结果 | 见 11.2 空状态 |
| 搜索失败 | 展示错误占位 + 重试，不清空关键词 |

### 6.4 内容详情统一规范

- 所有详情页共用底部操作区：**收藏按钮**（右）+ 分享（左，P1）。
- 详情页顶部为返回 + 标题（滚动后渐显）+ 分享。
- 详情页内容区支持图片预览（点击放大、双击缩放、左右滑动）。
- 详情页不支持评论、点赞、关注（X）。

### 6.5 内容标记规范

| 标记 | 用途 | 展示位置 |
| --- | --- | --- |
| 类型标签 | 资讯/教学/场地/装备 | 卡片左上角或标题前 |
| 难度标签 | ⭐入门 / ⭐⭐进阶（仅教学） | 教学卡片、教学详情 |
| 场景标签 | 室内/室外/网红出片/近郊（场地） | 场地卡片、场地详情 |

## 10. 双端数据同步方案（小程序 / APP）

### 10.1 同步原则

1. **服务端为唯一事实源**：收藏、用户信息、内容库全部以服务端为准，客户端不做独立副本。
2. **不搞实时推送**：首期不使用 WebSocket；采用"进入/刷新即拉取"的最终一致策略，允许秒级—分钟级延迟。
3. **不做游客收藏**：未登录状态客户端不允许写入任何收藏数据，从根上避免"本地收藏无法归属账号"的脏数据。
4. **写操作幂等**：收藏/取消收藏接口按 `(userId, contentType, contentId)` 幂等，双端并发点击结果一致。

### 10.2 账号打通路径

| 场景 | 行为 |
| --- | --- |
| 小程序首次登录 | wx.login → 后端建账号（绑定 openid），返回 userId + token |
| APP 微信快捷登录 | 同一 openid → 命中同一账号，数据直接可见 |
| APP 手机号登录 | 新建/命中手机号账号；若该手机号此前未绑定微信，则和小程序账号是**两个账号** |
| APP 绑定微信 | 手机号账号绑定 openid → 之后小程序微信登录进入该账号，两端合一 |
| 同一微信先在小程序建号，后在 APP 绑手机号 | 在小程序侧「账号与绑定」完成手机号绑定，或在 APP 侧走"微信登录后绑定手机号"，二者结果一致 |

**产品侧强制引导**：APP 手机号登录用户，若未绑定微信，我的页面常驻一条提示条：「绑定微信后，小程序里的收藏也能在这里看到 → 去绑定」。可关闭（本次会话内）。

### 10.3 收藏一致性策略

| 时机 | 行为 |
| --- | --- |
| 进入任一列表/详情页 | 拉取该页所需内容的收藏状态（随内容接口一并返回 `isFavorited`） |
| 下拉刷新 | 强制重新拉取，覆盖本地状态 |
| 点击收藏 | 乐观更新 → 调接口 → 失败回滚 |
| 从详情返回列表 | 使用详情页返回的最新状态同步列表对应卡片（本地事件传递，不重复请求） |
| 小程序/APP 切换（切前台） | 触发当前页状态刷新 |
| 收藏页 | 每次进入重新拉取，不做本地缓存 |

### 10.4 冲突处理

- 同一内容在 A 端收藏、B 端取消，短时间并发：以**服务端最后写入时间为准**（Last Write Wins）。
- 前端不做合并、不做弹窗冲突提示；用户下拉刷新即得到最终态。
- 极端情况（离线队列）：首期不做离线写队列，离线时收藏按钮点击直接提示「网络异常，请稍后重试」，不进入本地队列。

### 10.5 同步范围清单

**同步**

- 用户信息（userId、昵称、头像、绑定关系）
- 收藏集合（四类型）
- 收藏数量统计
- 内容库（四类型内容及其字段）

**不同步**

- 搜索历史
- 浏览历史（P2 才考虑同步）
- 本地缓存图片与播放进度
- APP 推送设置与小程序订阅设置
- 上次停留 Tab、滚动位置

### 10.6 双端差异清单（必须显式管理）

| 能力 | 小程序 | APP | 处理 |
| --- | --- | --- | --- |
| 登录 | 微信一键登录 | 手机号 + 微信 | 文案分支 |
| 分享 | 转发小程序卡片 / 朋友圈（P1） | 系统分享 / 复制链接 | 按端分支 |
| 视频全屏 | 原生全屏 | 原生全屏 + 横屏允许 | APP 允许视频页横屏，其他页面锁定竖屏 |
| 返回手势 | 物理返回键/左滑 | 系统返回键/手势 | 保持一致 |
| 深色模式 | 跟随微信（P1） | 跟随系统（P1） | 本期统一浅色 |

## 11. 状态规范：加载 / 空状态 / 异常 / 弱网

### 11.1 加载状态

| 场景 | 表现 | 规则 |
| --- | --- | --- |
| 首次进入列表页 | 骨架屏（3–5 个卡片占位） | 优先骨架，不用全屏转圈；骨架与真实卡片布局一致，避免跳动 |
| 详情页 | 头部图片区 + 标题占位骨架 | 加载完成渐显，不用闪白 |
| 图片加载中 | 占位底色 + 微光效果 | 加载成功淡入 |
| 图片加载失败 | 占位图标 + 尺寸保持 | 点击可重试单图（P1） |
| 上拉加载 | 列表底部 loading + 「加载中…」 | 加载中禁止重复触发 |
| 加载完成 | 「没有更多了」分隔文案 | — |
| 搜索中 | 搜索框内轻量加载指示 | 不遮挡结果区 |
| 登录中 | 按钮内 loading，禁用重复点击 | — |
| 收藏提交中 | 图标轻量脉冲，不弹全屏 loading | 8s 超时回滚 |

### 11.2 空状态（统一结构：插画 + 主文案 + 副文案 + 可选按钮）

| 场景 | 主文案 | 副文案 | 操作 |
| --- | --- | --- | --- |
| 收藏全空 | 还没有收藏内容 | 看到喜欢的资讯、教学、场地和装备，点收藏就能留住 | 去逛逛（回首页） |
| 单一类型收藏空 | 还没有收藏{类型} | 去{对应模块}看看有没有喜欢的 | 去{模块} |
| 搜索无结果 | 没有找到相关内容 | 换个关键词试试，比如"发球""出片场地" | 返回/清空关键词 |
| 分类为空 | 该分类内容正在更新中 | 先看看全部内容 | 重置为「全部」 |
| 筛选无结果（场地/装备） | 没有符合条件的内容 | 试试减少筛选条件 | 重置筛选 |
| 推荐流为空 | 内容正在准备中 | 稍后刷新再来看看 | 刷新 |
| 未登录（我的） | — | 登录后可收藏并在双端同步 | 登录按钮 |
| 搜索入口空（无输入） | — | 输入关键词开始搜索 | — |
| 反馈提交空 | — | 至少输入 5 个字 | 按钮禁用 |

**空状态通用规则**

- 空状态必须出现在**内容区域**，不得整页空白；顶部导航、筛选栏、底部 Tab 保持可见可操作。
- 插画不承载信息，文案承担解释职责。

### 11.3 异常状态

| 场景 | 表现 | 文案 | 操作 |
| --- | --- | --- | --- |
| 首屏请求失败 | 全内容区错误占位 | 网络开小差了，请稍后重试 | 点击重试 |
| 分页加载失败 | 底部提示条 | 加载失败，点击重试 | 重试 |
| 详情加载失败 | 内容区错误占位 | 内容加载失败 | 重试 / 返回 |
| 图片失败 | 单图占位 | — | 自动重试 1 次 |
| 视频失败 | 封面色 + 播放图标 | 视频加载失败，点击重试 | 重试 |
| 收藏失败 | 图标回滚 + toast | 操作失败，请稍后重试 | 可再点 |
| 登录失败 | toast | 登录失败，请重试 | 再次点击 |
| 内容已下架 | 卡片置灰 | 内容已下架 | 可取消收藏 |
| 接口 401（token 失效） | 静默清除本地 token | 登录已过期，请重新登录 | 下次需登录动作时触发登录 |

### 11.4 弱网与离线策略

1. 请求超时阈值：普通接口 8s，图片/视频 15s。
2. 弱网（<2G 表现）：降低首页 Banner 与瀑布流首屏数量（图片请求失败率高时降级为首条 3 条）。
3. 完全离线：展示"当前无网络"提示条（顶部细条），已加载过的当前页内容可继续浏览（本地渲染已获取数据），写操作一律提示失败。
4. 不实现离线包与预下载（X）。

## 12. 交互细则与手势规范

### 12.1 通用

| 规则 | 说明 |
| --- | --- |
| 触控热区 | 所有可点元素 ≥ 88rpx（≈44px）；图标视觉可小于热区 |

### 12.2 手势

| 手势 | 适用 | 行为 |
| --- | --- | --- |
| 左右滑 | Banner、图片轮播、标签栏 | 切换项 |
| 上滑 | 所有列表 | 加载更多 |
| 下拉 | 所有列表/首页 | 刷新（有 60rpx 阻尼 + 指示） |

### 12.3 动效（功能性，非视觉风格）

- 骨架 → 内容过渡：淡入 200ms，不位移。
- 收藏切换：图标 200ms 缩放反馈。
- 列表项移除（取消收藏）：高度收起 250ms。
- 不做页面级视差、不做装饰性入场动画（避免影响性能）。

| 单位 | 统一 rpx，字体不小于 24rpx（约 12px） |
| 横屏 | 小程序全局竖屏；APP 仅视频全屏允许横屏 |
| 安全区 | 底部 Tab 与底部操作栏避让安全区（iPhone 底部横条、安卓手势条） |
| 状态栏 | 自定义导航需按机型动态计算高度（沉浸式） |
| 键盘 | 搜索输入、反馈输入时页面自动上推，输入框不被键盘遮挡 |

### 13.2 布局要求

| 页面 | 布局 |
| --- | --- |
| 首页/资讯/教学 | 单列，左右安全边距 24rpx，卡片间距 24rpx |
| 场地/装备 | 双列瀑布流，列间距 16rpx，卡片宽度 = (屏宽 - 边距 - 列间距)/2 |

| 参数表 | 两列（键 30% / 值 70%），值列自动折行 |
| Tab 栏 | 固定底部，高度 98rpx + 安全区 |

### 13.3 图片与视频

- 所有图片走 CDN 尺寸变体（列表用缩略、详情用原图），列表图宽不超过屏宽 2 倍。
- 图片等比裁剪，禁止拉伸；瀑布流图片高度由后端返回宽高比计算，避免加载后跳动。
- 图片懒加载：距视口 1 屏内开始加载。
- 视频：首帧封面单独给出，不加载视频本体直到点击播放。

## 14. 接口约定（前后端契约）

> 以下为前端所需最小接口集合，路径与字段为建议值，最终以后端实现为准，但**语义与返回值必须满足前端状态机**。

### 14.1 内容类

| 方法 | 路径 | 说明 | 关键返回 |
| --- | --- | --- | --- |
| GET | `/api/v1/home/recommend` | 首页 Banner + 推荐流 | `banners[]`、`items[]`（分页） |
| GET | `/api/v1/contents` | 内容列表（通用） | `list[]`、`hasMore`、`total` |
| GET | `/api/v1/contents/{id}` | 内容详情 | 内容全字段 + `isFavorited` |
| GET | `/api/v1/search` | 全局搜索 | `groups`（按类型分组）、`total` |

**`/api/v1/contents` 入参**

| 参数 | 说明 |
| --- | --- |
| type | news / course / venue / gear |
| category | 分类标签（多值） |
| scene | 场景/风格标签（多值，场地与装备用） |
| page / size | 分页（size 固定 10） |
| withFavorite | 是否返回 `isFavorited`（默认 true） |

### 14.2 收藏类

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/favorites` | 新增收藏，body `{contentType, contentId}`，幂等 |
| DELETE | `/api/v1/favorites` | 取消收藏，body 同上，幂等 |
| GET | `/api/v1/favorites` | 收藏列表，入参 `type`、`page`、`size` |
| GET | `/api/v1/favorites/count` | 四类收藏数量 |

**统一响应结构**

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

**收藏写接口返回**

```json
{ "code": 0, "data": { "contentType": "gear", "contentId": "g_1001", "isFavorited": true, "updatedAt": "..." } }
```

### 14.3 账号类

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/wx-login` | 小程序/APP 微信登录，入参 `code` | 
| POST | `/api/v1/auth/phone-login` | APP 手机号登录，入参 `phone`、`code` |
| POST | `/api/v1/auth/bind-wx` | 绑定微信，入参 `code` |
| GET | `/api/v1/user/profile` | 用户信息 + bindStatus + 收藏计数 |

### 14.4 其他

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/feedback` | 意见反馈：`type`、`content`、`contact` |
| GET | `/api/v1/search/hot` | 热词（P1） |
| GET | `/api/v1/config` | 全局配置（模块开关、文案、Tab 配置） |

### 14.5 前端状态机要求（必须由接口支持）

1. 列表接口必须返回 `hasMore`，前端不靠 `length < size` 推断。
2. 内容接口必须返回 `isFavorited`，否则前端无法在首屏渲染正确收藏态。
3. 收藏写接口必须幂等且返回最终状态，前端以返回值为准而非本地推断。
4. 所有接口需返回明确的业务 `code`，前端据此区分"无权限/内容下架/系统错误"。
5. 分页需支持 `cursor` 或稳定 `page`（避免内容变更导致重复/漏项，建议 cursor）。
